# 游戏词库中文校准界面原型

**PROTOTYPE — 可丢弃，等待界面评选。** 原型分支 prototype/localization-calibration，基于已完成本地化的 db348cb，不合并到 main 或 integration。

设计问题：175 条游戏词库的汉化校准，应采用批量对照表、逐条审阅，还是按证据风险组织的看板？当前没有获选方案，等待使用者反馈；正式实现时重写选中的结构。

## 运行与入口

已有项目依赖时，一条命令：

    npm run prototype:calibration

内网临时地址：

- A 对照工作台：http://192.168.1.8:5174/?prototype=calibration&variant=A
- B 逐条审阅：http://192.168.1.8:5174/?prototype=calibration&variant=B
- C 风险看板：http://192.168.1.8:5174/?prototype=calibration&variant=C

三种结构位于原应用的根路由，共用真实品牌页头及游戏词库上下文。底部浮条和左右方向键切换方案；输入框、下拉框及文本编辑区域中的方向键正常编辑。URL 保存方案选择，切换不清空本次审阅。原应用 App 不在原型模式挂载，因此不会读取或写入规划库存。

原型只在 Vite 开发模式启用。生产构建不包含原型组件、样式或切换浮条。

## 已对齐范围

P0 游戏词库优先，现有 175 条记录全部取自 samples/text-library/library.json：62 航行、64 边界、15 奖励、15 目的地、3 基底、5 形状、11 字段。按冲突/缺失、仅来源、已校准的顺序呈现。P1 执行流程、P2 策略/操作界面、P3 帮助/历史文案暂不加入本原型。

- 英文优先展示原工具原句，来源英文可展开对照；字段依据实际解析器，未知英文留空，不反向编造。
- 当前中文使用现有显示函数，保留完整描述与界面简称。冲突奖励的程序生成文字与来源候选分开显示。
- 来源证据状态和人工审阅结果彼此独立；“审阅通过”不会修改客户端校准状态。
- 条目包含位置/用途、英文、当前中文、状态；展开后有作用范围/形状示意、来源、候选文本、样本路径、建议与备注。
- 支持类别、关键词、证据、审阅结果筛选及计数。原型状态可展开查看。
- 审阅保存在内存，刷新清空；主动点击“导出本次建议”下载 JSON。没有保存到游戏词库或规划状态。

## 三个待评选结构

A：高密度位置/英文/中文/状态表，右侧详情和编辑，适合横向比较与批量筛查。

B：左侧审阅队列，右侧一条纸面式双语核对单，适合阅读长句并逐条填写建议。

C：冲突/缺失、仅来源、已校准三个风险列，点击卡片展开详情，适合决定先审哪一组。
