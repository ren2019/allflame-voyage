# #16 边界适配分实施记录

范围：统一规格 #21 的独立边界适配分。部署未改，原求解评分、策略材料保护及库存状态未改。

## 规则来源与初版数据

`src/data/borderAffinity.json` 是独立、静态、可版本管理的完整策略 × 边界表，版本 `3.29-border-affinity-1`。覆盖当前七策略、64 个稳定边界 ID，共 448 条显式记录；现有选择器的 65 个选项中含“无边界词缀”，并无第 65 种边界。

每条记录包含相对权重、中文解释和来源 ID。来源固定到实施基线中的策略说明、边界机制，以及 #21 的初版权重约定。0–10 是维护者依据这些资料整理的初始匹配程度，非实测收益评级；没有从求解器的百分比启发值直接换算收益。0 表示本版没有专项适配加分，不表示该边界没有一般价值。

关键例子：神圣石边界在两种依赖该边界的策略中权重10；50%稀有怪边界权重5，所以“神圣石 + 两条50%稀有怪 + 九条经验边界”总分20。十二条50%稀有怪是60，但仍独立提示必要神圣石边界缺失。魔法怪流的十二条“至少为魔法”是120，十二条稀有怪边界为0。此分数不要求归一到100，不设重置门槛。

宝藏锚与锚地目的地的沉没宝藏没有因名称相似直接混为一类。按连接变化的边界只获静态方向权重，解释明确实际净效果仍受连接影响；计算函数和面板均不接收连接、库存或盘面。

## 可见行为

九宫格之前显示整组“边界适配分”，尚未导入或摆盘也可用。可展开十二条贡献、依据与规则版本。重复按出现次数累计；策略必要边界另行提示。未选策略、未录满十二条、未知策略／边界和非有限权重都不显示虚假完整分数。

## 验证

按已批准的 TDD 边界先获得规则缺失的失败，再实现逐项累计；非有限配置用例先看到 NaN 被误报完整，随后修正。整页先确认缺少面板失败，再集成只读组件。

- 5项规则输入输出用例：独立预期20、60、0、120；重复、必要边界、策略切换、不完整及未覆盖、无效权重、全表解释与来源覆盖。
- 2项离线Playwright流程：空库存先看分；相同边界空盘／满盘结果不变；切换策略重算；展开明细不改变完整导出状态；真实边界控件填入后显示1/12；高分仍缺必要边界；未知规则不冒充零分。
