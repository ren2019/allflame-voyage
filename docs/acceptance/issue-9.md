# #9 离线 BDD 集成与现场检查点

当前结果：**自动化通过；真实国服游戏现场待验证**。本交付完成可自主执行的集成验收，#9 和父规格仍需现场证据，不能据此关闭整体任务。

统一命令：

```sh
npm ci
npm run verify
```

依赖安装可需要网络；安装完成后的 verify 不读取实时 PoEDB、原站或任何外部服务数据。它依次运行 Vitest 全部公开接口/原版回归、原有边界 OCR、离线文本库审计、本地 HTTPS 启停/CA检查、生产构建和完整 Playwright BDD。浏览器仅允许本地测试源，外部分析脚本/字体/站点全部阻断，service worker 禁用；不复用其他开发服务。真实 Windows 检查为独立 `npm run test:windows`，不混入离线入口。

`docs/acceptance/coverage.json` 是27组场景/七类故事的机器契约，`coverage.md` 是可读账本。验证器检查 feature 的全部27个标题、七个故事 ID、必要 fixture/测试存在、实际报告中的文件/测试名称/通过数量及无 skip/fail。全部输入有 portable SHA-256；旧报告或修改后的代码/资料不能被静默当作本次通过。solver、scoring、connectivity 与规格基线20a694b的原文件 SHA-256 相同；七策略测试另核对原 ID、权重、布局、材料、银行数量、限制与原默认权重。

最终本分支执行：**478 项单元/公开边界测试通过；26 个浏览器场景通过，零跳过；4 项本地部署检查通过；原有 OCR 64/64及别名12/12通过；文本库离线摘要审计与生产构建通过；27/27场景组和7/7故事具有执行证据**。输入摘要、时间和完整报告已保存在 `evidence/verification-summary.json` 及其引用报告。本次首次完整集成故意不宽松处理报告缺失：Playwright默认清理test-results导致单元报告被删除，入口实际失败；改为独立 verification-results 目录后通过。缺报告/缺fixture的公开审计测试经历缺失模块失败→实现通过，验证不是静默skip。

主流程在 #7 原场景上加强而非复制：通过文本框实际导入两张真实国服原文，再与12个人工内部实例一起载入，真实 UID/完整字段始终保留。实际填12边界并从策略卡选择点金速刷，点击求解和候选；九步每次真实剪贴板写入与当前实例的独立姓名/原句/区域等级 oracle 一致，复制后库存不减。核销保留一个确认存活及五个未使用实例，其中含两张真实海图；补5张人工空白图、重新固定存活实例、更改边界，再求解九个人工模型。两个真实End/Straight没有冒充完整人工四向摆盘或游戏内实际放置。失败重试、七策略、其他核销/备份分支复用已有真实控件场景。
