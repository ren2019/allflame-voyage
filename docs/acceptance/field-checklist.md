## 一次真实航程

1. Mac Mini 在项目目录执行 `npm run verify`，通过后更新手动站点：`npm run site:update`；使用 `npm run site:status` 核对地址。记录当前提交和时间，导出一份现有 JSON 作为操作前备份。
2. Windows Edge 打开 `https://192.168.1.8:8443`。地址栏应无证书错误，页面为简中。保持同一浏览器和地址；不要用人工 fixture 替换自己的真实库存。
3. 在国服游戏中逐张手动 Ctrl+C 复制已测绘海图，粘贴本页，核对名称、目的地、区域等级、形状、数量/硫磺及航行词缀。先分别导入，再批量粘贴；重扫相同库存时数量不应增加。未识别项保留原文并反馈，不能靠手动猜词缀变成“已验证”。
4. 按游戏当前规划板填写十二个边界，核对每个槽位的中文原文和位置。选择已有策略/设置，求解并点击一个明确标示可执行的候选。核对九张实际库存实例及朝向；仅参考候选不能当成功。
5. 打开放置指南。每步点击复制后，在真实游戏海图库存中粘贴搜索，确认命中的就是当前高亮格所需海图。由玩家手动 Ctrl+左键放置。顺序为左下、中下、右下、左中、正中、右中、左上、中上、右上。逐步记录搜索是否命中、是否误命中及实际格/朝向；第九步后核对完整游戏摆盘。网页复制阶段库存不应减少。
6. 玩家自行完成实际航程。结束后点击网页完成航程，按游戏结果逐张确认保留海图存活或被消耗。比较游戏库存与网页库存：仅本盘实际消耗实例被移除，未使用和存活实例保留，九格清空，边界和配置保留。
7. 补充真实库存并更新游戏边界，再规划第二航程；检查没有引用已消耗实例。刷新网页并做一次真实 JSON 导出/载入，核对库存、摆盘、边界和设置恢复。

以上操作全部由玩家在游戏中手动完成。验收工具没有通过 SSH、按键脚本、鼠标宏或自动化来操作游戏。
