## Problem Statement

国服玩家希望使用现有 Allflame Voyage Solver 规划自己持有的海图，但游戏复制的简体中文文本无法导入。已使用两份真实国服原文复现：英文站显示 `skipped 1 unrecognised`；台服站合并和单张导入均显示加入0张、跳过1项“不是海圖物品”。两个站点均未正确拆分合并的中文物品文本。

玩家需要从库存导入一直完成到摆盘、游戏内放置和航程核销，而不只是让两张样本显示导入成功。首版个人自用，部署于 Mac Mini，内网 Windows 游戏电脑通过浏览器访问。

## Solution

以英文原版为改造基础，新增国服简中解析与词缀/目的地映射，简中化现有核心界面，保留原版评分、求解、七个策略及已有交互。Mac Mini 手动提供内网站点；规划数据继续保存于同一 Windows 浏览器和同一站点地址，使用现有 JSON 完整状态备份。

工作包含独立的国服词缀与文本库制作，以及原有完整旅程的 BDD 自动化验收。主旅程为：手动启动站点→Windows打开→游戏复制海图→单张/批量导入→填写12个边界→选择策略/保留设置→求解→选择可执行候选→按9步定位放置→实际航程→确认存活→核销→更新库存和边界后继续。

导入失败沿用现有数量与类别汇总提示；国服关键航行词缀缺失或未匹配时整张拒绝，避免效果缺失的海图静默参与规划。

## User Stories

以下是已确认七类故事的细化，不扩展首版产品范围。

1. 作为 Mac Mini 运维者，我希望手动启动和停止内网站点，以便开发期间按需提供规划工具。
2. 作为国服玩家，我希望从内网 Windows 浏览器打开该网站，以便在运行游戏的电脑上规划。
3. 作为国服玩家，我希望导入单张游戏复制的海图，以便用自己的真实物品规划。
4. 作为国服玩家，我希望一次导入多张海图，以便快速录入库存且每张正确分隔。
5. 作为国服玩家，我希望海图名称、区域等级、目的地、形状、奖励和航行词缀正确识别，以便规划依据与游戏一致。
6. 作为国服玩家，我希望高级复制文本的数值范围、附注、标点和 Windows 换行能正常解析，以便无需手工清理游戏原文。

13. 作为国服玩家，我希望使用原有权重、保留保护、中心选择和布局设置，以便按自己的库存和优先级规划。

15. 作为国服玩家，我希望区分可执行候选和不可执行参考方案，以便不把缺材料或连接无效的摆盘当成成功。
16. 作为国服玩家，我希望补充材料或调整现有设置后重新求解，以便解决本次不可行的情况。
17. 作为国服玩家，我希望点击候选后实际载入其海图和朝向，以便后续指南对应我选择的方案。
18. 作为国服玩家，我希望复制国服可匹配的定位文本，以便在游戏中找到当前格对应海图。
19. 作为国服玩家，我希望按原有九步顺序复制并推进放置指南，以便将当前摆盘落实到游戏中。
20. 作为国服玩家，我希望复制和放置指南不会提前消耗规划库存，以便完成航程后再核销。
21. 作为国服玩家，我希望刷新或重新打开同一浏览器地址后恢复规划状态，以便无需重复录入。
22. 作为国服玩家，我希望导出和导入完整 JSON 状态，以便备份库存、摆盘、边界和设置。

25. 作为国服玩家，我希望核销后清空摆盘、保留边界与配置，并使用更新后的库存继续规划，以便完成下一航程。

## Implementation Decisions

- 基础仓库为 `one-more-map/one-more-map.github.io` 的 fork `ren2019/allflame-voyage`，源码检查基线为 `20a694ba8afb6ce497a67287b67c68a6b244e5fd`。保留原版 MIT 许可和出处。
- 新增国服解析方言及批量物品头分隔；涵盖带空格的稀有度标签、区域等级、奖励头部、基底标记、目的地、形状和原文高级属性附注。既有英文与韩文方言及容错继续兼容。
- 语言适配发生在解析、数据映射、界面展示和游戏定位文本生成的边界；内部海图形状、区域、词缀及策略标识保持稳定，评分效果和权重保持原版。
- 国服基底词缀缺失、为空或无法映射到已有关键航行效果时，整张物品进入现有拒绝结果；同批有效项继续导入。界面只要求原有数量/类别汇总，逐项名称和原因在解析输出验收。
- 读取区域等级而非物品等级或需求等级。显式属性正文的奖励不能重复累加到头部总值；本区域奖励与全航程效果分开表示。
- 保留原版去重与实例语义，包括同批多份、整批重扫、没有去重文本的实例。去重字段仅是原版过滤后的显式属性，不承诺完整复制文本存储，不借移植重写数量语义。
- 沿用原版基底原句和显式负面属性字段保留；完整采集样本独立保存用于验收。
- 七个现有策略为 Alc & Go、Anchorfield Fishing、Speedrun Strongboxes、Meatfish、Magic Ethereal、Divine Border Rares、Divine Strongboxes。区分材料要求、硬约束与软评分偏好；不把偏好改造成新强制规则。
- 保留十二个边界位置与九格映射，四角各有两个直接边界，中间边格一个，中心没有直接边界。直接边界索引0–11对应格序为0、1、2、2、5、8、6、7、8、0、3、6；九格按从上到下、从左到右编号0–8。
- 候选实际载入九格实例和朝向；放置顺序沿用左下、中下、右下、左中、正中、右中、左上、中上、右上。复制不核销；完成航程才按使用及存活情况移除实例并清空摆盘。
- 状态仍在浏览器保存，JSON 导出/导入完整规划状态，包括库存、非空摆盘、边界、策略、保护、权重和持久设置；不增加后端数据服务或跨设备同步。
- 部署为 Mac Mini 手动启动的内网静态站点。Windows 一键复制必须在实际访问地址验证；安全上下文属于部署兼容点，不是中文解析失败原因。优先用部署方式支持现有复制能力，不授权新增复制降级 UI。

### 独立交付：国服词缀与文本库

- 使用用户指定的 PoEDB `/cn/` 正式站及对应 `/us/` 页面，采集基底、目的地、航行/边界词缀、奖励及可取得的形状和字段文本。避开 PTR，不按表格行号盲目连接双语数据。
- 数据包含现有141个词缀标识的完整覆盖清单：43个相邻、19个全航程、64个边界、15个归并奖励类型；另含15个目的地、5种形状和复制字段。网页表格行数不是项目标识数。
- 每条记录保留中英原文、真实来源标识、URL与定位、采集日期、可见版本、快照摘要、作用范围、档位和数值范围、内部标识、映射依据、客户端样本引用及校验状态。未知原生标识填空值，不自行编造。
- 优先以相同 metadata 或 mod/stat 标识对齐；只有语义复核的条目明确标记为语义复核。真实国服客户端复制文本是实际格式的校准依据，PoEDB 是候选资料而非腾讯官方复制文本接口。
- 区分已校准、仅来源、缺失、未匹配和冲突。当前初步种子有15个目的地、2条词缀映射、2种真实形状；139条词缀仍待逐条核对，其余3种形状未采集。
- 已知 PoEDB 当前显式奖励档位/作用范围及部分硫磺译名与原版或客户端样本不同，必须记录版本与语义冲突；不为了补中文覆写评分参数。缺证据的条目不能标为校准完成。
- 收录原版范围外的额外基底或机制可标记未匹配，不因此新增策略或功能。网页模板与真实物品全文分开保存，派生测试数据不能冒充真实采集。
- 数据库工作独立于应用适配，产出离线、可追溯映射与覆盖报告，供解析和展示消费。未解决的资料缺口作为明确的数据任务，不能用跳过必要测试冒充完成。

## Testing Decisions

测试边界沿用此前确认的公开解析入口及完整浏览器用户流程。算法验证使用既有求解、连接与评分入口；不为测试增加新的产品界面或重构核心算法。

已有测试先例包括英文/韩文真实复制文本解析、区域映射、去重实例计数、策略目的地规则、库存保护选择、Session Plan 及浏览器状态恢复的公开行为测试。BDD 场景描述业务结果，不要求引入特定 Gherkin 运行器；实现工具按项目现状选择。

### 国服解析与词库

- 两份真实样本分别与合并导入成功。断言完整名称、区域等级83、目的地、标准形状与连接、头部奖励、基底原句和效果标识。
- 第1张为蛤蜊海架/End，数量110%、硫磺75%、`adj-crab-1`；第2张为深渊平原/Straight，数量110%、硫磺60%、本区域群大小5%、另有全航程`voy-pack-1`效果。
- 分别覆盖 Windows 换行、全角冒号、带空格的稀有度、高级roll/range及不可调整后缀。
- 派生负例覆盖未知词缀、缺少基底标记和词缀、空基底行、混合有效/无效批次、非海图、未测绘、缺少或未知形状。负例有明确预期拒绝数量及解析原因。
- 用区域等级71、物品等级83、需求等级66的派生样本证明字段没有混淆；不顺带重写既有英文/韩文回退规则。
- 保留既有同批多实例、重复重扫及无去重文本的行为。奖励正文不重复累计，语言匹配不改变效果或权重。
- 参数化验证每个已对齐的词库条目映射到正确已有ID，区分档位和作用范围，覆盖报告显示未验证项。

### 完整浏览器旅程

- 使用隔离且为空的浏览器存储再打开网站；通过实际控件导入、填写边界、选择策略、求解、选择候选、逐步复制、刷新、JSON往返和核销。
- 固定数据分别覆盖七个策略。每组有明确实例、配置、材料条件和已验证的可行见证；随机求解不比较唯一最优排列、固定排名或与台服相同的逐格输出。
- 可执行候选必须满九格，使用不同的实际库存实例并满足所选连接与保护规则。不可行fixture不能被标示为可执行。
- 十二个边界按逐位置隔离及四角叠加验证；采用已核对中文名称及内部ID，中心没有直接边界效果。
- 一条贯穿集成场景实际选择候选并核对载入实例/朝向，点击9次复制并下一步，受控剪贴板记录每次真实写入内容，第9次结束指南；复制阶段库存不减少，随后核销的正是该盘。
- 初始8张不可行库存补入第9张后再次求解成功；第一航程核销后补库存、更新边界、第二次规划成功，不能引用已消耗实例。
- 刷新恢复库存、边界、摆盘和配置。JSON往返包含非空摆盘、保护、权重等全部持久字段，前后同盘评分一致。
- 核销区分未使用、已消耗、确认存活和确认未存活实例；九格清空，边界与配置保留。
- 核心控件、策略说明和成功/失败提示符合简中词表，游戏定位采用真实国服原句或已核对映射。

### 数据制作与执行证据

七策略、重试、双航程和边界数据集是独立测试数据制作项。必须有实际数据、来源、预期及可行性证明后才能标ready；当前登记不等于数据已存在。离线数据用于自动化，每次验收不依赖第三方在线网站。

完整真实采集不以两个样本代替；人工内部模型或派生文本明确标注。原版字段保留不等于完整复制文本存储。已有英文/韩文测试继续通过。

### 目标环境验收

Mac Mini 手动提供网站，实际 Windows 浏览器能从约定地址访问并导入国服海图、完成一次可执行规划。验证现有复制权限和实际国服游戏内搜索/放置。自动化字符串匹配和受控剪贴板只能证明网页行为，不能代替现场游戏验证。未具备目标环境时记录未验证，不报告成功。
