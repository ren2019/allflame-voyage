# 国服航海摆盘工具：首版 PRD

状态：用户已确认七条用户故事和关键航行词缀未匹配时拒绝导入的规则。本文是开发前需求依据；BDD 场景尚未接入运行器，不能视为自动化已通过。

开发规格已发布为 [GitHub Issue #1](https://github.com/ren2019/allflame-voyage/issues/1)，本地正文见 `spec.md`。后续任务拆分以该规格为父项，本文保留产品范围说明。

## 问题与目标

国服玩家复制海图后，英文原版及台服版都无法导入。两份真实国服原文在英文站提示 `skipped 1 unrecognised`；台服站合并与分别导入均失败，提示 `已加入 0 張，跳過 1 項（不是海圖物品）`。

首版将现有英文源码适配国服简体文本与界面，使同一个玩家能完成原有规划流程。保留评分模型、求解算法、七个策略及现有交互；适配语言边界，不扩展产品功能。

## 用户与运行环境

唯一玩家在内网 Windows 游戏电脑上使用浏览器；同一个人手动启动 Mac Mini 上的网站。网站仅需内网访问，开发期间不要求开机自动启动。库存和设置保存于同一 Windows 浏览器、同一站点地址；使用现有 JSON 导出和导入备份，不增加跨设备同步。

场景定义在 `acceptance/port.feature`，字段预期在 `../samples/README.md`。七个策略为原版 Alc & Go、Anchorfield Fishing、Speedrun Strongboxes、Meatfish、Magic Ethereal、Divine Border Rares、Divine Strongboxes。

完整主流程包含候选实际载入、九次复制推进、库存不足后重试，以及核销后补库存、更新边界并再次规划。测试数据登记与边界位置映射见 `acceptance/fixtures.md`。

## 适配规则

- 国服物品类别、带空格的稀有度标签、区域等级、奖励字段、基底属性标记、目的地和形状进入对应解析规则。
- 连续复制的多个物品正确分隔；兼容 Windows 换行、样本中的全角冒号、高级属性数值范围和“数值不可调整”后缀。
- 中文航行词缀映射到现有内部标识，不更改对应效果或策略权重。
- 国服关键航行词缀缺失或未匹配时拒绝整张海图，沿用现有失败提示。不增加待确认列表或人工补全界面。
- 奖励头部总值不与显式属性正文重复相加；本区域奖励与全航程效果分开表示。
- 物品等级和区域等级是不同概念；当前两张样本均为 83，不能据此证明两者不同值时也正确。
- 保留原有去重、实例、手动摆盘、策略保护、保存和航程核销语义。现有英文和韩文解析继续通过回归测试。
- 沿用原版的字段保留：基底词缀原句存入 `implicitText`，过滤后的显式负面属性存入 `rawText`；不承诺库存保存完整 Ctrl+C 原文。完整采集样本独立保存用于验收。
- 首版关键界面、策略说明与失败提示使用简中；游戏匹配文本以真实国服文案为准。

## 自动化验收方式

1. 解析与数据行为：通过现有解析公开入口读取真实 fixture，断言有意义的完整字段、词缀作用范围及拒绝结果。由真实样本派生的换行、未知词缀等负例标为派生用例，不伪称真实采集。
2. 浏览器用户流程：隔离浏览器存储，通过真实界面导入、选择边界/策略、求解、选择候选、复制指南、刷新、JSON 往返与航程核销，观察库存和页面状态。复制使用受控剪贴板记录每次实际调用内容，而非只检查页面文字。BDD 不要求引入 Cucumber；可使用适合项目的测试工具实现相同场景。
3. 求解回归：使用可验证的固定可行/不可行库存。随机搜索不比较唯一排列或固定排名；比较可执行性、库存实例唯一性、连接、策略保护及同一摆盘的评分。七个策略各有代表性回归用例。
4. 游戏定位：自动化断言生成文本能匹配 fixture 中目标、并检查原有九格填充顺序。真实游戏搜索结果和 Windows 实际内网访问需目标环境验证，不能以浏览器模拟代替游戏验收。

不将实时第三方网站纳入每次测试，避免网络或上游改动让本地回归不稳定。原站用于建立参考行为，自动化针对本地待交付版本。

## 首批样本及覆盖

已取得端点形蛤蜊海架与直线形深渊平原各一张，基底词缀分别对应 `adj-crab-1` 和 `voy-pack-1`。足够先建立真实输入失败→成功的开发闭环。

完整国服验收仍需补齐其他形状、目的地、航行词缀及边界文案。已知缺口可作为测试数据任务推进；不能把只通过两张样本宣称为全量兼容，也不能靠推测文案宣称真实样本覆盖。

## 独立工作：国服词缀与文本库

从用户指定的 `https://poedb.tw/cn/` 采集海图基底、目的地、形状、航行词缀及边界词缀，使用英文同页与数据标识对齐现有内部 ID。结果保留来源 URL、获取日期、原始文本、作用范围、数值范围、映射证据和校验状态。

PoEDB 简中文案是候选数据来源，不自动等同于腾讯客户端 Ctrl+C 格式。已有两份真实样本用作校准；差异记录为显式别名或冲突，保留客户端版本证据。网页字段说明与实际复制文本的空格、标点、高级属性附注分别记录。

该工作独立产出可追溯的结构化文本清单和覆盖报告，先完成范围与来源核对，再供解析和 UI 适配使用。边界/航行词缀数据任务可以先做，浏览器自动化仍使用离线快照；每次验收不在线依赖 PoEDB。调查记录位于 `research/poedb-text-library.md`。

## 部署与现场验收

手动启动 Mac Mini 服务后，Windows 通过约定的稳定内网地址访问并完成导入与规划。现有一键复制在普通内网 HTTP 下可能受浏览器限制，部署时必须检查；这是环境兼容项，不是中文解析失败原因，不授权新增复制降级 UI。

## 不在首版范围

公众共享、多用户账户、跨设备同步、新策略、新求解算法、数量管理新交互、待确认库存、人工补全 UI、剪贴板采集器及截图 OCR。上游已有相关入口的存在不代表首版要适配那些辅助采集能力。
